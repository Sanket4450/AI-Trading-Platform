01

What this task produces

Outcomes and scope

This plan creates the repository skeleton and its tooling. It does not implement strategies, broker calls, risk rules or trading logic. The result is a workspace where those later milestones can be added without moving folders or rewiring the build.

Workspace foundation

A pnpm workspace at the repository root, orchestrated by Nx, with cached build, lint, test and typecheck targets and a visible project graph.

Three runnable apps

apps/web, apps/api and apps/worker live directly under the root apps/ folder — never nested inside another app or package.

Twelve shared packages

Framework-agnostic TypeScript packages for domain contracts, engines, adapters, persistence, configuration, notifications and observability.

Local infrastructure

PostgreSQL and Redis through Docker Compose, Drizzle migrations, environment templates, test folders, docs and Azure deployment placeholders.

Definition of done

  • pnpm install completes from a clean clone with one lockfile.
  • pnpm nx graph lists web, api, worker and all twelve packages with dependency edges.
  • pnpm nx run-many -t typecheck, lint, build and test pass.
  • docker compose up -d starts healthy PostgreSQL and Redis containers.
  • pnpm dev starts the dashboard on :3000, the API on :8000, and the worker process.
  • GET /api/v1/health returns a healthy response and the worker logs a ready queue connection.
  • pnpm db:generate produces a Drizzle migration without schema drift.
▲
Explicitly out of scope: strategy implementation, Upstox authentication, order placement, risk-policy logic, backtest metrics, live trading and production deployment. Those belong to R2–R8 in context/deployment-order.md. This task stops at a verified skeleton.
◆
The context/ folder is source material, not scaffolding. It already contains the architecture, strategy, risk, execution and backtesting specifications. Do not delete or reorganise it; later tasks read from it.

Shape of the workspace

Architecture at a glance

The repository is a modular monolith with a separate worker process. The dashboard never talks to the database or broker directly; it calls the API. The API and worker share domain packages but never import each other. Broker and persistence details stay behind ports and adapters.

Presentation & application

apps/web · :3000Next.js App Router. Strategies, backtests, trading, risk, performance, settings.
apps/api · :8000NestJS HTTP API. Validates commands, coordinates workflows, exposes reports.

Dependency rules

  const config = app.get(ConfigService);

  app.use(helmet());
  app.enableCors({

  app.enableShutdownHooks();

}

Official CLI scaffolds drift from Nx expectationsProjects missing from the graph or targets not cached.Thin project.json shims delegate to package scripts; no custom executor logic. Verify with nx show projects.

Redis data loss or evictionLost jobs and stale locks.Append-only persistence, noeviction, health checks; managed Redis in production.
Accidental live tradingReal financial loss.TRADING_MODE=offline default; validated configuration; kill switch; R8 promotion gates.
Secrets in the repositoryUnauthorised broker or database access.Ignore .env, commit only the template, scan before pushing.
Timezone mistakes around the sessionWrong opening range, late square-off.Store UTC, test with Asia/Kolkata, use NSE session constants from configuration.

Non-negotiable guardrails

  • No app imports another app. The API is the only HTTP surface.
  • No package imports NestJS, Next.js or React.
  • No strategy imports a broker adapter or calls the broker directly.
  • No live order path without risk-engine validation.
  • No session without a recorded strategy version and configuration snapshot.
  • No committed secret, and no production database pointed at by a local .env.
